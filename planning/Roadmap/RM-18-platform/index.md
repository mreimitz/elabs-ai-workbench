* [Platform hardening — the cross-cutting operability items](item.md) - Deliver the operability items no feature plan owns: a first-run demo seed, in-app docs and changelog, a redacted diagnostics bundle, a migration upgrade-test harness, fleet-scale performance budgets and the consolidated owner-acceptance walks.
* [Owner acceptance — the one consolidated checklist (WP 1.6)](owner-acceptance-consolidated.md) - Every pending owner-acceptance check across every roadmap ledger, grouped into four sittings by the one credential each needs.
* [Platform hardening — work-package status ledger · PRIORITY: MEDIUM (rolling)](STATUS.md) - Living state for the platform plan, read and updated by /next-wp platform. A box is ticked
* [WP 1.2 - in-app docs and changelog (the shipped user guide readable inside the running app, plus one context-aware Help control in the top bar)](wp-1.2-in-app-docs.md) - Bundles planning/user-guide/DC-* and CHANGELOG.md into the web build at build time, serves them at /docs, and adds a single route-aware Help control to the AppShell top bar so every view reaches its own page of the guide without a per-view edit.
* [WP 1.3 - diagnostics bundle (one-click redacted export for bug reports, proven secret-free by test)](wp-1.3-diagnostics-bundle.md) - RM-18 Phase 1. Ledger: STATUS.md. One endpoint and one Settings action that produce a self-contained, redacted diagnostics document — versions, environment sans secrets, DB table counts and sizes, migration level, recent errors — whose secret-freedom is asserted by an automated test rather than trusted to review.
* [WP 1.4 - upgrade-path test harness (captured fixture DBs, migrate, invariant assertions)](wp-1.4-upgrade-harness.md) - Platform hardening WP 1.4. Ledger: STATUS.md. Replaces rewind-simulated old databases with captured fixture databases, so every future migration is proved against a shape that actually existed rather than one the test author remembered.
