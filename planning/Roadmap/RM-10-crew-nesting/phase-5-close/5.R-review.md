## 1. Scope + refute method

A **refute** pass, not a summary (D-CN10, invariant §6.8). For each probe I constructed the adversarial
input that *would* break the invariant if the implementation were wrong — a branchy depth-2 tree, a
save-then-mutate cycle, a zero-allocation child, a nested `auto` crew, an empty-crew-ref grant, a nested
unready server, a nested `best_of_n` whose result flows into a parent judge, a cyclic replay log — ran
it, and reached a verdict:

- **REFUTED** — a passing adversarial test mounts the attack and the system holds (cited against the
  product `file:line`, or the code path that makes the attack structurally impossible).
- **FINDING** — a failing repro (kept as a `.skip`/xtest with a `// FINDING:` comment). **None occurred.**

All probing drives the existing injectable seams (`resolveCrew` / `runAgent` / `judge` / `isServerRunReady`
DI + the `agentRunnerMode:'structured'` stub the 2.R suite uses) — **no provider key, no real tenant, no
live child spawn**. Where 2.R already refuted an engine invariant, the same attack was re-mounted against
the **now-integrated** code (Phases 3–4 changed `board.ts`, `mission-trace.ts`/`session-report.ts`, and
the web reducers) to prove no regression (§4, P-REG1).

Line numbers below are as of the reviewed tip; the anchors are stable functions/guards, not exact lines.

## 3. Findings

**None.** All 21 probes REFUTED. No `WP-5.fix-*.md` spec was authored and no STATUS `blocked` line is
needed. Two scope clarifications (not defects, carried from 2.R, both re-confirmed here):

1. **Single-crossing spend overshoot (pre-existing, non-amplified).** The tree-wide budget trip is
   checked *after* a leaf's cost is added [`orchestrator.ts:1201`], so the single leaf that crosses the
   cap (and any others already in flight, ≤ the root `maxParallel` via the shared limiter) still counts —
   bounding overshoot to `≤ maxParallel` leaves' cost. This is **identical to a flat mission's**
   long-standing trip behaviour; crew nesting does **not** amplify it (the shared accumulator + shared
   trip + shared limiter are the ceiling). P-BUD1's tests rig evenly-dividing leaf costs to assert the
   strict bound honestly.
2. **`releaseTurn` awaiter cleanup lives on the session-runner path.** The `hitl.ts:318-342`
   per-turn teardown is exercised only via `runAgentTurn`, which the deterministic **structured** stub
   seam bypasses (it is covered by the existing turn-engine/HITL unit tests). P-HITL2 verifies the
   observable deny→honest-partial behaviour via the stub seam; a **live** HITL awaiter-cleanup walk is an
   owner-acceptance item (§5).
