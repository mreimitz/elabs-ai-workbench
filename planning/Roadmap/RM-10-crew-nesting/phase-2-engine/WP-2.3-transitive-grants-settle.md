# WP 2.3 — Transitive grant intersection, readiness recursion & tree-wide settle/abort/steer

**Phase:** 2 — Recursive execution engine · **Size:** M · **Depends on:** 2.1 · **Model:** Opus

## Objective
Make the security envelope and run-control reach **every level** of a nested crew tree. Grant intersection must compose **transitively** down the path (level-2 ∩ level-1 ∩ level-0), never re-widening from a nested crew's own Access tab (D-CN9 / D-HF5 across N levels); the pre-run MCP/OAuth readiness gate must recurse into nested crews' grants; and `stop()` / `stopAgent()` / `steerAgent()` / the honest-settle helpers must reach an agent at any nesting depth so a top-level stop halts the whole tree. This closes the R6 escalation and abort-reachability risks the budgets-security map enumerates, building on the recursion seam WP 2.1 laid down.

## Why / references
- **D-CN9** (transitive non-escalation, frozen scope boundary) + **D-HF5** extended to N levels + map §2 **R6** / §6 "Grant intersection / no escalation": `effectiveAgentGrants` (`grants.ts:69` (`../../apps/api/src/hub/tools/grants.ts`)) already composes (drop-if-absent + set-intersection is associative), but the transitivity only holds if the **enclosing slot's already-effective scope** is threaded as the nested `parentScope` — not re-derived from the sub-mission's session row (per **D-CN6** every sub-mission keeps `session_id = the root chat session`, so `getSession(mission.sessionId).toolScope` at `orchestrator.ts:655` (`../../apps/api/src/hub/missions/orchestrator.ts`) would re-widen a nested spawn back to **level-0**).
- **missionUnreadyServers** (`orchestrator.ts:563` (`../../apps/api/src/hub/missions/orchestrator.ts`)) iterates `mission.plan.agents` flat and is the pre-run gate consumed by `approve()` (`orchestrator.ts:527` (`../../apps/api/src/hub/missions/orchestrator.ts`)) — it must recurse into crew-ref units via the WP 1.1 cycle-safe crew resolver (`resolveCrew`, `orchestrator.ts:226`/`:467` (`../../apps/api/src/hub/missions/orchestrator.ts`)), intersecting down each path.
- Map §5 / §6: `RunningMission` (`orchestrator.ts:273` (`../../apps/api/src/hub/missions/orchestrator.ts`)) holds one `missionAbort` + one flat `agentAborts` Map per **top-level** mission; `stop`/`stopAgent`/`steerAgent` (`orchestrator.ts:591`/`:605`/`:620` (`../../apps/api/src/hub/missions/orchestrator.ts`)) key off `this.running.get(missionId)`. Child session ids are globally unique, but nested aborts currently register nowhere the control methods can reach; `settleSkippedChild`/`settleFailedChild` (`orchestrator.ts:1216`/`:1226` (`../../apps/api/src/hub/missions/orchestrator.ts`)) already operate per child-session id (level-agnostic).
- **Invariant 5** (conventions.md — transitive non-escalation): grants intersect down the path; nested plan grants only ever **narrow**. Do **not** union a nested crew's servers upward (`unionRosterServerGrantsIntoScope`, `grants.ts:115` (`../../apps/api/src/hub/tools/grants.ts`)) — that is exactly the R6 escalation. **D-CN9 frozen boundary:** touch no `ASSISTANT_ENTITY_KINDS` / `SCOPE_WRITE_TOOLS` / `deriveAssistantScope`.

## Design

**1. Transitive grants — thread, don't re-derive.** `effectiveAgentGrants` stays pure and behaviour-unchanged (its drop-if-absent + set-intersection already composes: `effectiveAgentGrants(L2plan, effectiveAgentGrants(L1plan, L0scope)) = L2 ∩ L1 ∩ L0`). The load-bearing change is at WP 2.1's crew-ref recursion seam: the sub-mission's child spawn must receive the **enclosing crew-ref slot's `effectiveGrants`** (already `L1 ∩ L0`) as its `parentScope`, **not** `getSession(subMission.sessionId).toolScope` (which is the root chat session per D-CN6 and re-widens to L0). Concretely, factor the parent-scope source in the run path so the nested run takes an **injected `parentScope` override** (default: the session-derived scope, so the top-level mission is byte-identical to today). Every nested level applies `effectiveAgentGrants(planned.toolGrants, injectedParentScope)` and passes its own result down as the next level's `parentScope`. Amend the `effectiveAgentGrants` doc-comment to state the N-level transitive contract and the D-CN6 re-widen hazard so the rule is discoverable at the function.

**2. `missionUnreadyServers` recursion.** Compute the transitive reachable-server set: walk `mission.plan.agents`; for a leaf, `effectiveAgentGrants(planned.toolGrants, parentScope)` as today; for a **crew-ref** unit (carries `crewId`), resolve it with `resolveCrew` (the WP 1.1 memoised cycle-safe resolver) and recurse through the crew's members, computing each member's effective grant against the **running intersected scope** for that path (so a server dropped by intersection at any level is unreachable and correctly **not** flagged). Carry the same **run-time visited-set of crewIds + depth counter** WP 2.1 introduced, so a mutated/cyclic graph can't loop the gate (D-CN4 belt-and-suspenders). Dedupe by `serverId`; check each with `isServerRunReady`. `approve()` then blocks the whole tree with the existing actionable auth-required error naming the nested server.

**3. Tree-wide settle/abort/steer.** WP 2.1 threads the shared abort **signal** through `TopologyContext` (nested runSlots short-circuit on it and chain their per-agent aborts to it — abort forwards **down**). WP 2.3 adds the **registry bookkeeping** so the top-level control methods can reach a specific nested agent: when the recursion seam materialises a sub-mission row, register a `RunningMission` control in `this.running` **keyed by the sub-mission id**, with its own `agentAborts` Map (its direct children) and a `missionAbort` wired so the **enclosing** abort forwards into it (`enclosingAbort.addEventListener("abort", () => nested.missionAbort.abort(), { once: true })`) — a strictly **downward** cascade (stopping a sub-mission never aborts its parent/siblings). Because child sessions are globally unique and a level-2 agent's `child.missionId` equals its **sub-mission** id, `stopAgent(subMissionId, agentId)` and `steerAgent(subMissionId, agentId, text)` then resolve through `this.running.get(subMissionId)` with **no change to those methods**. A top-level `stop(topMissionId)` aborts `topAbort` → the enclosing slot's per-agent abort (WP 2.1 chaining) → the nested `missionAbort` → its per-agent aborts → the level-2 agent aborts. Each nested run `this.running.delete(subMissionId)` in its `finally` (no leak). The nested run reuses `settleSkippedChild`/`settleFailedChild` **unchanged** for its own children, so a top-level abort drives every descendant to a terminal (`aborted`) state.

Keep every change additive and guard the widened `crewId?` deref (a planned unit without `crewId` is a leaf — the existing path). Do not relax the propose gate; nested runs are born only inside the deterministic recursion engine.

## Acceptance
- [ ] `effectiveAgentGrants` is unchanged in behaviour; its doc-comment states the N-level transitive rule + the D-CN6 re-widen hazard; the grants unit test proves `effectiveAgentGrants(L2, effectiveAgentGrants(L1, L0)) === L2 ∩ L1 ∩ L0` and that an L1-dropped server/tool is **not** re-granted by an L2 plan.
- [ ] A nested spawn's `parentScope` is the **enclosing slot's effective grants**, never `getSession(subMission.sessionId).toolScope`; a level-2 agent's child-session `toolScope` in the integration test equals the transitive intersection (a root-dropped server is absent at level-2).
- [ ] `missionUnreadyServers` recurses into `crewId` units via `resolveCrew` under the visited-set + depth guard, dedupes by `serverId`, and never flags a server that intersection makes unreachable; `approve()` blocks a tree whose **nested** crew grants an unready server and names it; an all-ready tree is not blocked.
- [ ] `unionRosterServerGrantsIntoScope` is **not** applied to nested crews (no upward widening); nested plan grants only ever narrow.
- [ ] Each running sub-mission is registered in `this.running` (own `agentAborts`, downward-chained `missionAbort`) and removed in its `finally`; `stopAgent(subMissionId, agentId)` and `steerAgent(subMissionId, agentId, text)` reach a level-2 agent with no change to those methods' contracts.
- [ ] A top-level `stop()` aborts a level-2 in-flight agent: it settles `aborted` with no report, the sub-mission and the tree end `stopped`/partial, every descendant child session is terminal, and no `this.running` entry leaks.
- [ ] `settleSkippedChild`/`settleFailedChild` are reused unchanged (no per-level duplication) and honestly settle skipped/failed children at every level.
- [ ] `ASSISTANT_ENTITY_KINDS` / `SCOPE_WRITE_TOOLS` / `deriveAssistantScope` untouched; the `kind==='chat'` propose gate and the withheld `mission.propose_plan` builtin untouched; every widened `crewId?` deref is guarded.
