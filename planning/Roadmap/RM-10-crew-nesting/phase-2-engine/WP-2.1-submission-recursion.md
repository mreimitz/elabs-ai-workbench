# WP 2.1 — Sub-mission spawn + recursion at `runSlot`/`runOneAgent`

**Phase:** 2 — Recursive execution engine · **Size:** L · **Depends on:** 1.1, 0.2 · **Model:** Opus

## Objective
Make a saved crew execute *inside* another crew at run time (D-CN2): a planned unit carrying a `crewId` is expanded into its **own sub-mission**, run under the **child crew's own topology**, and its synthesised answer is projected into **one stamped `HubAgentReport`** returned through the existing `HubAgentRunResult` channel — so every parent topology stays agnostic about whether a slot was a leaf agent or a whole sub-crew. This is the recursion heart of the plan. It threads a **shared** abort signal, cost accumulator, and concurrency limiter across all levels (never fresh per level — that is the R1 concurrency-multiplication trap), and adds a **run-time** visited-crewId + depth guard as belt-and-suspenders behind WP 1.1's author-time check (D-CN4). The `kind:'chat'` propose gate and the withheld `mission.propose_plan` builtin are **untouched** — the sub-mission row is created directly by this engine, never via `proposePlan` (D-CN1).

## Why / references

- **D-CN3 (minimal, correct-by-default here)** — a **shared** cost accumulator + abort signal + concurrency limiter threaded through `TopologyContext` across all levels; do NOT mint fresh per level. 2.1 guarantees aggregate ≤ root ceiling via the shared accumulator + shared trip; the `min(requested, parentRemaining)` subdivision math is **WP 2.2**.
- **D-CN4** — run-time visited-set of crewIds along the path + depth counter → reject re-entry / over-depth **loudly**. Never trust the author-time check still holds (the graph can mutate between save and run).
- **D-CN6** — the sub-mission `hub_missions` row uses the columns WP 0.2 adds (`parent_mission_id`, `depth`, `root_mission_id`) with **`session_id = the ROOT chat session`**; `hub_sessions.kind` and the propose gate are not relaxed.
- **D-CN1 / D-CN9** — propose gate + withheld builtin unchanged; `ASSISTANT_ENTITY_KINDS`/`SCOPE_WRITE_TOOLS`/`deriveAssistantScope` untouched; transitive grant/autonomy N-level composition is deferred to **WP 2.3** (2.1 wires the obvious pass-down only).

## Design

**1. Per-level crew-ref planned units (`topologies.ts`).** Today `instantiateCrewPlan` (`:440`) does `roleById.get(member.agentId); if (!role) return;` — a `crewId`-only member (WP 0.1 made `agentId` optional) would be silently dropped (map breakage #3). Branch it:
- `member.crewId` set → push a **crew-ref** `HubPlannedAgent` via a new `crewRefToPlannedAgent({ crewId, index, ask, member })`: sets `crewId` (WP 0.1 field), a synthetic `key`, `roleName`/label from the child crew name (resolve the name via the WP 1.1 helper, else a stable `Crew <id>` fallback), a **curated brief** from `composeCrewBrief(ask, member)` (the mission ask + the member's focus — never the parent transcript, D-CN9), and a placeholder `model` (child crew members carry the real models; `normalizePlannedModels` at `orchestrator.ts:394` backfills any tier/empty from `session.model`).
- `member.agentId` set → the existing role path, unchanged.
This function is the **per-level** plan builder, called at every level (root via `proposePlan`→`instantiateCrew`, each nested level via `runSubCrew`), so a grandchild `crewId` again becomes a crew-ref unit one level down. Revise the `:22–24` depth-1 comment to describe the D-CN2 amendment.

**2. Shared runtime (`orchestrator.ts`).** Introduce a single `MissionRunRuntime` created **once** at the root `runMission`, holding: the root `control` (`missionAbort` + `agentAborts` Map — the exact object stored in `this.running` under the ROOT id, so `stop()`/`stopAgent()` reach every level), a shared `cost: { total: number }` accumulator, a shared `budget: { tripped: boolean; cap: number }` + `tripBudget()` (aborts every entry in the shared `agentAborts`), and a shared **`ConcurrencyLimiter`** (a tiny async semaphore, `createConcurrencyLimiter(rootMaxParallel)`). Extract the current `runMission` body (spawn → `runSlot` → `runTopology` → `settleSkippedChild` → `synthesize` → `updateMission`) into `runMissionLevel(mission, runtime, level, ask, sink)` where `level = { depth, visitedCrewIds }` and `ask` is passed in (root passes `firstUserText`; a sub-mission passes its **curated brief**, fixing map isolation breakage #12). Root: `runMission` builds the runtime and calls `runMissionLevel(rootMission, runtime, { depth: 0, visitedCrewIds: new Set() }, firstUserText(...), sink)`.

**3. `runSlot` becomes shared + branches on crew vs leaf.** Rebuild `runSlot` as `buildRunSlot(mission, runtime, level, sink)` closing over the **shared** runtime, so every level's `runSlot` shares abort/cost/limiter/trip while carrying its own `depth`/`visitedCrewIds`. Inside:
- Short-circuit on `runtime.control.missionAbort.signal.aborted || runtime.budget.tripped` (shared).
- `slot.planned.crewId` set → **crew branch**: `runSubCrew(...)` (below). Do **not** acquire a limiter permit and do **not** add its returned `costUsd` to `runtime.cost.total` (its nested leaves already accrued into the shared accumulator — this is the no-double-count rule).
- else → **leaf branch**: register the per-agent abort into the shared `runtime.control.agentAborts` (chained to the shared `missionAbort`), `await runtime.limiter.acquire()`, run `runOneAgent(...)` exactly as today, `finally` release + cleanup, then `runtime.cost.total += result.costUsd; if (cap > 0 && runtime.cost.total >= cap) runtime.tripBudget()`.
Acquiring the permit only on the **leaf** branch (never while a crew slot delegates) bounds global concurrent model calls to the root's `maxParallel` and cannot deadlock. `TopologyContext.isBudgetTripped` / `missionAbort` at every level read the **shared** flag/signal.

**4. `runSubCrew(mission, slot, runtime, level, abortSignal, sink)` — the recursion.**
1. `childDepth = level.depth + 1`. If `childDepth >= caps.maxDepth` → **loud reject** (below).
2. `crewId = slot.planned.crewId`. If `crewId ∈ level.visitedCrewIds` → loud reject (cycle). The path-visited set ∪ the depth cap jointly guarantee termination even if the graph mutated after WP 1.1's save-time check.
3. Resolve the immediate child crew via the WP 1.1 crew-resolution helper / `resolveCrew(crewId)` → `{ crew, roles }`; unresolvable → loud reject. Resolution is **level-by-level** (D-CN2) — never materialise the full transitive tree here.
4. Build `childPlan = instantiateCrewPlan({ crew, roles, ask: <curated brief = slot.planned.brief>, autonomy: mission.autonomy })`, then `normalizePlannedModels` + `clampPlanToBudgets(childPlan, caps, autonomy)` (agent-count/server clamp; the budget subdivision is 2.2 — the shared accumulator + shared trip is 2.1's real ceiling guarantee). Belt-and-suspenders total-agent backstop: if adding these leaves would push a **shared** running leaf count past `caps.maxTotalAgents`, loud-reject the over-cap branch (the propose-time tree estimate is 2.2).
5. `childMission = repository.createMission({ sessionId: rootSessionId, topology: crew.topology, autonomy, plan: childPlan, budgets, parentMissionId: mission.id, depth: childDepth, rootMissionId: mission.rootMissionId ?? mission.id })` — the WP 0.2 fields; `sessionId` is the **root** session (D-CN6). Created directly, no `proposePlan`/`approve`/HITL auto-approve (D-CN1).
6. `outcome = await runMissionLevel(childMission, runtime, { depth: childDepth, visitedCrewIds: new Set([...level.visitedCrewIds, crewId]) }, /*ask*/ slot.planned.brief, sink)` — the sub-mission spawns its own `kind:'agent'` children (parented per the existing loop, `missionId = childMission.id`), runs `runTopology(crew.topology, childCtx)` with the **shared** runtime, then synthesises. `runMissionLevel` returns the synth outcome (`synthesisReports`, `partial`, the settled sub-synthesis prose/message + `costUsd`).
7. **Project → one report** (D-CN2, reusing `projectTranscriptToReport`/`stampReport`): summary = the sub-mission's synthesised answer prose; `citations` = `mergeAgentCitations(outcome.synthesisReports)`; `confidence` = most-conservative across members (`min` of low<medium<high); `openQuestions` = deduped union; set the WP 0.1 nesting fields `subMissionId = childMission.id`, `topology = crew.topology`, `childReports = outcome.synthesisReports`. `stampReport(projected, slot.child, crewRoleName)` so the parent synthesis remaps by `slot.child.id` exactly like a leaf.
8. Emit `agent_report` for `slot.child` into the **expanding mission's** (parent) log carrying the projected report + rolled-up cost/tokens, and `setSessionLifecycle(slot.child.id, { costUsd, tokensIn, tokensOut })` — mirroring `runAgentViaSession:1024/1029`, so the parent topology sees the sub-crew as one normal `agent_report`.
9. `updateMission(childMission.id, { status: aborted? "stopped":"completed", costUsd: <sub-tree subtotal>, endedAt })` for per-level attribution (3.2 renders it), and `return { report: stamped, costUsd: subtotal, tokensIn, tokensOut, aborted }`.

**Loud reject** = settle `slot.child` as failed (`settleFailedChild`) with a clear message ("crew nesting exceeded max depth N" / "circular crew reference C" / "child crew unresolved"), `logger.warn`, and return `{ report: undefined, costUsd: 0, … , aborted: false }` so the branch counts toward an honest **partial** — never an infinite loop, never a silent skip, and never a whole-tree crash from one mutated branch.

**Synthesis abort + cost:** `runMissionLevel` must synthesise via the **shared** `missionAbort` (not `this.running.get(childMission.id)`, which is unregistered) — thread an explicit optional `abortSignal` into `synthesize` (default keeps the root's current `this.running` lookup, so root behaviour is byte-identical). The sub-synthesis events persist under the root session tagged with `childMission.id`; the root chat renderer's mission-scoped filtering (board/report tree-awareness is **WP 3.1/3.2**) keeps them from surfacing as the root's own answer — 2.1 only guarantees the sub-synthesis is captured for the projection and attributed to the child mission id.

## Acceptance
- [ ] A crew whose member carries `crewId` produces a **crew-ref** `HubPlannedAgent` (`crewId` set, curated brief) from `instantiateCrewPlan`; an `agentId`-only member is unchanged (both proven by test).
- [ ] At run time a crew-ref slot runs a nested `runTopology` under the **child crew's own topology** and returns exactly **one** `HubAgentReport` through `HubAgentRunResult`, stamped on `slot.child` (`agentSessionId`, `roleName`, per-citation `agentRef`) with `subMissionId`/`topology`/`childReports` set; the parent topology code is untouched.
- [ ] A child `hub_missions` row is created by the engine with `parent_mission_id` = the expanding mission, `depth` = parent+1, `root_mission_id` set, and `session_id` = the **root** chat session — and **not** via `proposePlan` (the `kind:'chat'` gate + withheld `mission.propose_plan` builtin are unmodified; grep confirms `orchestrator.ts:330` unchanged).
- [ ] The shared abort/cost/limiter are threaded through all levels (no fresh per level): a nested tree's aggregate leaf spend is proven **≤** the root's `min(requested, maxBudgetUsd)` via the shared accumulator + shared trip, and global concurrent leaf runs never exceed the root `maxParallel` (both stub-tested).
- [ ] Run-time re-entry (`crewId` already on the path) and over-depth (`childDepth >= caps.maxDepth`) each **loudly** reject: a warn log + a failed `slot.child` + an honest partial branch — never an infinite loop, silent skip, or whole-tree crash; a `maxTotalAgents` overflow branch is likewise rejected.
- [ ] `top-level stop(rootMissionId)` and `stopAgent(rootMissionId, nestedChildSessionId)` reach in-flight nested leaves (they register into the shared `control.agentAborts`); the sub-synthesis is aborted by the shared `missionAbort`.
- [ ] `ASSISTANT_ENTITY_KINDS` / `SCOPE_WRITE_TOOLS` / `deriveAssistantScope` and `SCOPE_EXEMPT_ACTION_TOOLS` are untouched (D-CN9); no new DB migration and no new runtime dependency introduced by this WP.
- [ ] Gate green (`pnpm typecheck && pnpm test && pnpm build && pnpm lint`).
