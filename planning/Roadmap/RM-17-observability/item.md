# Observability — fleet monitoring, search and issues

## Goal

Build the monitoring layer on top of the session contract: metrics over time, full-text search with a filter grammar and saved views, a human-feedback backbone, console depth, watch rules, fleet issues, a pricing editor and scheduled digests.

## Why it matters

The app recorded every run but offered no way to see the fleet, search it, be alerted by it, or turn a recurring failure into a tracked issue.

## Milestones

- [ ] Phase 1 — metrics, search and the filter grammar.
- [ ] Phase 2 — dashboard tabs and the runs feed.
- [ ] Phase 3 — console depth and lineage.
- [ ] Phase 4 — watch rules and notifications.
- [ ] Phase 5 — fleet issues, pricing and digests.
