# Assistant Hub V1 Fixes — Implementation Wave (2026-07-20)

This wave implements every finding from `mission-session-analysis-2026-07-20.md` (F1 through F9) plus the two capability upgrades the analysis motivated: a universal web-search chain and a JS-native attachment-ingestion pipeline. All work follows the three principles from the analysis: model context equals UI context, capabilities are tools rather than UI affordances, and one model contract per model class.

## What changed, by root cause

### The mission memory spine (F1, F2, F3, F7)

The observed failure was a mission whose results the model could never see again. Four changes close the loop end to end.

1. The synthesis turn now runs on a model that can actually receive its instructions. `pickSynthesisModel` (missions/roster.ts) prefers the override, then the parent session model, then the first structured-capable plan model, and never an `assistant|` facade model. The observed session would have synthesized on `claude-sonnet-4-6` instead of a facade model that dropped the entire reports digest.
2. After synthesis, the orchestrator persists a `mission_digest` event: a hard-capped, per-agent record of findings and ALL open questions. `reconstructMessages` folds it into every later turn as an assistant turn, the compactor preserves it verbatim, and the synthesis message itself is now labeled ("Mission synthesis, composed from N agent reports") so later turns cannot misattribute it.
3. `mission.list` and `mission.report` are new read-only builtins reconstructing from the session's own events; `artifacts.read` closes the same gap for artifacts (a later turn can now re-open the report it wrote earlier). All three are default-granted; agent children still need explicit planner grants.
4. A `mission_followups` event carries the deduped, agent-attributed open questions. The mission board renders them as chips (outside the collapse, so they survive the done-board auto-collapse); one click proposes a follow-up mission. The planner receives the previous mission's digest and the recent conversation as a fenced read-only context block, so follow-up briefs build on actual results.

### Second missions and the end of orchestration theater (F4, F5)

`promptModeFor` now maps mission-mode sessions to a new `mission-followup` addendum that names the real path (`mission.propose_plan`, `mission.report`) and explicitly forbids simulating agents or staging fake work with `tasks.*`. The `mission.propose_plan` grant and the post-turn routing bridge now cover top-level mission sessions, and the server-side one-live-mission invariant is unchanged. The task-builtin description carries the same rule, so it holds in every mode.

The style contract is a new prompt layer present in every assembled prompt, including planner, synthesizer, critic, and subagent role prompts: no emoji or decorative unicode anywhere (prose, artifacts, GenUI strings), no filler enthusiasm, sentence-case headings, user requests override. The GenUI rules gained "text and title props are PLAIN text". Before this wave no style rule existed anywhere in the stack.

### Web search that works on every model (F6)

`web.search` now materializes as the provider-native tool when the model supports it (anthropic, openai, google) and otherwise as an app-level fallback builtin running a provider chain: Tavily key, then Serper key, then a self-hosted SearXNG URL, then a keyless DuckDuckGo HTML scrape that is honestly labeled degraded. Results normalize to one shape (title, url, snippet, optional answer box) with a 15-minute in-memory cache. Configuration:

```
HUB_SEARCH_TAVILY_KEY=...     # recommended first key (1,000 free searches/month, no card)
HUB_SEARCH_SERPER_KEY=...     # real-Google alternative (answerBox quality, $0.30/1k)
HUB_SEARXNG_URL=http://...    # self-hosted keyless option (enable json format in settings.yml)
HUB_SEARCH_DUCKDUCKGO=off     # disable the zero-config scrape if undesired
HUB_MISSION_SYNTHESIS_MODEL=  # optional F1 override
```

Two behavior fixes ride along. Every non-agent session now gets web tools by default, scoped or not (the old rule silently dropped search from any custom Access scope); mission agents still require an explicit planner grant. And whenever search is exposed, the tools layer carries a claude.ai-style freshness rule: for present-day facts, search before answering, answer from snippets when they contain the answer, fetch only for depth. When no search exists at all, the prompt says so honestly instead of staying silent.

`web.fetch` extraction upgraded from regex tag-stripping to Defuddle (the maintained Readability-class extractor) with markdown output and the old extractor as deterministic fallback, so a fetched article reads as an article.

### Attachments every model can read (ingestion)

Documents attached to chat now convert to markdown in-process before history reconstruction: pdf via unpdf, docx via mammoth plus turndown (GFM tables), xlsx via SheetJS into per-sheet pipe tables with honest row caps, pptx via officeparser, html via turndown. Conversions cache by content hash, never throw (an unconvertible file keeps the old raw-part behavior), and a pdf keeps its raw file part alongside the markdown so vision-capable models still see the original. The decision to go JS-native rather than a Python markitdown sidecar is documented in the analysis research: LobeChat and AnythingLLM ship exactly this stack, markitdown's docx engine is the same mammoth library, and a sidecar would add a Python prerequisite on end-user Macs for marginal gain. SheetJS installs from the official cdn.sheetjs.com tarball (the npm registry copy is years stale).

### Facade hygiene and report quality (F8, F9)

The role template scrubs "Not yet configured" workforce placeholders and omits unset fields entirely, so profile noise never reaches a live agent prompt. Facade (`assistant|`) agents get their role instructions and report expectations folded into the brief itself, because the facade drops system prompts by design. The the vendor answer stream gained an overlap guard (`dropStreamOverlap`) that removes frame-tail duplication of eight or more characters, the shape observed as "visualizations:izations:izations:" in settled messages, while leaving legitimate short repetition untouched. The report-extraction prompt now enforces a citation floor: when a transcript names the data system it queried, the report cites that system rather than returning an empty citations list.

## New and changed surfaces

New events: `mission_digest`, `mission_followups` (HUB_EVENT_TYPES is now 41; contract test updated; additive, replay-compatible).
New builtins: `mission.list`, `mission.report`, `artifacts.read`, plus the `web.search` fallback (composed, never in ALL_BUILTINS).
New prompt surfaces: `style` layer, `mission-followup` mode addendum, prompt version `hub-prompt-1.1.0`.
New dependencies (apps/api): defuddle, jsdom, mammoth, turndown, @joplin/turndown-plugin-gfm, unpdf, officeparser, xlsx (cdn.sheetjs.com 0.20.3), @types/turndown (dev).

## Acceptance walk (re-run of the failing session)

1. Create a mission session on a Claude/GPT model, ask for the multi-perspective sales report, approve the plan with the the vendor-Analysts crew (facade agents).
2. Verify the synthesis message quotes the agents (it must not be a fresh the vendor answer; the synthesis model in the transcript must be the session model), and the board shows follow-up chips after completion.
3. Ask "pick one open question per agent and investigate again". Expect a plan proposal (plan_proposed), not `tasks.create` theater; the model may also read `mission.report` first.
4. Click a follow-up chip. Expect a seeded proposal whose briefs reference the previous results.
5. Check the report artifact and chat prose contain no emoji.
6. In a session on an Ollama or subscription model, ask "what's the weather today in New York". Expect a `web.search` call and a snippet-grounded answer (degraded note if no key is configured).
7. Attach an xlsx and a docx to a chat on a text-only model and ask about their contents. Expect real answers from the converted markdown.

## Known limits and follow-ups

The planner turn itself still runs on the session model; a facade-model session cannot plan missions (unchanged, now documented). The DuckDuckGo fallback is rate-limited by nature and marked degraded; configure a Tavily or Serper key for reliable search. The overlap guard is a conservative heuristic pending a captured raw tenant stream to reproduce the duplication exactly. Scanned PDFs (no text layer) still fall back to the raw file part; an optional Docling/OCR sidecar toggle is the designed phase-2 path. `context-inspector` shows attachment bytes rather than converted markdown (display-only).
