Suite list capped at `FLEET_REPORT_SUITE_RUN_LIMIT = 20` with `totalSuiteRuns` always reported. Posture renders a named gap — `roadmap/security-posture/` is unbuilt, so it says "unmeasured rather than clean" and substitutes no other measurement; an optional `FleetPostureProvider` seam exists (exercised by a test, **not wired in production**). `registerReportRoutes` gained one **appended** parameter (the four advisor read ports, the same set `registerAdvisorRoutes` gets); `digest-schedule.test.ts` updated only to pass it. No migration, no new dependency, no touch to `ASSISTANT_ENTITY_KINDS`/`SCOPE_WRITE_TOOLS`/`deriveAssistantScope` (verified by diff). +16 api tests, incl. two real-HTTP route tests that assert the embedded advisor report is byte-equal to `GET /api/advisor/report?scope=fleet` on the same app. Gate re-run by the orchestrator in the worktree: **typecheck · test · build · lint all green (exit 0)** — api **3190 pass / 0 fail**, web 3103 passed / 5 skipped / 302 files, Biome clean over 1432 files. **Not verified:** never run against a real fleet — every fixture is seeded SQLite rows, suite aggregates were inserted directly rather than produced by the orchestrator, and no provider-backed or graded run exists; never exercised in the built container or a browser (there is no UI for this report); the posture section's **populated** path is stub-only and its shape is this WP's design, not one the security-posture plan has agreed to; determinism is proven within one process against one seeded DB under an injected clock, not across processes.
